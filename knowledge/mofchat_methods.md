# How MOFChat answers a question

1. Planner: a language model turns the question into a structured JSON plan. Options are free cloud models (Google Gemini Flash, Groq GPT-OSS / Qwen, OpenRouter Nemotron) or local Ollama models (Llama 3); rate-limited or failing models are skipped automatically. The plan holds the intent, numeric constraints, objectives, metal and open-metal-site filters, application, MOF IDs and number of results. If the LLM is unavailable, a deterministic rule-based parser produces the plan instead.
2. Validator: the plan is checked before anything runs. It rejects unknown columns and operators, non-numeric or physically impossible values and invented MOF IDs. It converts percentages to fractions, merges duplicate bounds and flags contradictory ones. A numeric threshold that does not appear in the question is turned into a preference instead of a hard filter, and for application questions (e.g. CO2 capture) ranking objectives the question does not mention are dropped so that the application preset decides the ranking. Errors are sent back to the LLM for up to two self-corrections; after that the rule-based parser is used.
3. Executor: the validated plan is compiled into a parameterised SQL query. Column names come from a whitelist and values are bound parameters, on a read-only SQLite connection. The LLM never writes SQL that is executed.
4. Ranking: one objective means a plain sort. Two or more objectives (for example high surface area and low density) are ranked with the NSGA-II selection operator: non-dominated sorting into Pareto fronts, then crowding distance to keep a diverse set of trade-offs (Deb et al., IEEE Trans. Evol. Comput. 6, 182–197 (2002)). If no MOF satisfies all constraints, MOFChat says so and shows the closest MOFs ranked by total constraint violation.
5. Similarity: "MOFs similar to X" uses embeddings from a self-supervised FT-Transformer (masked-descriptor autoencoder) searched with FAISS cosine similarity.
6. Property prediction: an XGBoost surrogate model predicts accessible surface area or void fraction from cheaper geometric descriptors, with a split-conformal 90 % prediction interval. SHAP values (Lundberg & Lee, NeurIPS 2017) explain each prediction feature by feature. An FT-Transformer regressor gives a second, deep-learning opinion.
7. Knowledge retrieval (RAG): definitions, heuristics and passages from the ChatMOF paper are embedded with Sentence-BERT (all-MiniLM-L6-v2) and retrieved with FAISS. They are given to the LLM with source tags.
8. Answer validation: the LLM writes the explanation from the verified results table. Every MOF ID in the answer must be in the results, every number must match the table, the question or a known constant, and every comparison claim about named MOFs ("A, B and C have surface areas above 6000 m2/g", "on the first Pareto front") must hold for each of them. Near-miss IDs are corrected and anything unverifiable is flagged. The exact database rows are always displayed next to the text.
